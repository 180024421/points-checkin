# 积分签到工具（CheckinTool）使用说明

## 功能

- 卡密激活（`app_key=points-checkin`，设备绑定）
- 多账号入池：
  - **自助**：官方客户端切号后点「采集」/「粘贴 Trae token」
  - **统一登录**：导入账密 → 优先官方登录 API → 失败再有头 Playwright（可过验证码）
- **本机跑**：早晚双窗口调度 + 托盘常驻 + 开机自启
- **服务器代跑**：上传 **token**（不上传明文账密）；可「立即服务器代跑」
- **今日看板**：已跑 / 未跑 / 失败
- **积分记录** + **实时日志**（可清理）
- 失败自动重试（网络 / Trae 9074）

## 安装与启动

开发调试：

```bat
pip install -r requirements.txt
playwright install chromium
python -m checkin_tool
```

对外交付：打成 EXE

```bat
build_gui.bat
```

产物：`dist\CheckinTool.exe`（无控制台窗口）。首次若用统一登录，本机仍需安装过 Chromium（`playwright install chromium`）。

## 导入账密统一登录

1. 「导入账密」填产品（workbuddy / traework）+ 邮箱或手机 + 密码；可勾选立即登录
2. 批量格式每行：`provider,username,password[,label]`
3. 「统一登录(全部账密)」或「管理已存账密」里对单条登录
4. 成功后自动写入账号列表，可直接本机签 / 代跑

说明：WorkBuddy / Trae 多为 OneID / OAuth，纯密码 API 常常不可用，工具会自动开浏览器；遇扫码或强验证码时请改回「采集 / 粘贴 token」。账密仅本机 DPAPI 加密。

## 多号怎么采（自助）

1. 打开 WorkBuddy / TraeWork，登录号 A → 点「采集」
2. 退出并登录号 B → 再点「采集」
3. 列表会出现两个账号；可分别设「本机跑 / 服务器代跑」

TraeWork 若提示无法自动解密 token：先打开客户端登录，再「粘贴 Trae token」（设备头会自动带上）。

## 今日与日志

- 「今日看板」看谁跑了、谁还没跑、谁失败
- 「积分记录」看每次查询/签到拿到的积分与连签
- 「实时日志」看正在跑的过程；可清理实时日志或跑批日志
- 定时签到时一个账号出错只影响它自己：日志里会出现「XX 执行异常: ...」，后面的账号照跑，早晚两个窗口也照跑（以前一个账号抛错会把整天的自动签到静默停掉）
- 「未开放」是单独一档：活动没开始、签到入口未开放时既不算领到积分，也不算异常，不会标绿也不会进失败统计（以前这类会被写成「已签到」，晚窗就不再补跑了）
- 积分只在供应商真的返回数字时才显示：拿不到就留空，不再用 200 之类的占位数（以前 TraeWork 响应里没带积分会显示 200）

## 自动同步

打开程序不用再手点着刷新，顶部「已同步 HH:MM:SS · 每 5 分」那个标签就是同步状态：

- 启动约 4 秒后自动同步一次，之后每 `auto_sync_minutes`（默认 5 分钟）自动查一遍本机账号的当前积分；「哪些号跑了」（含服务器代跑结果）走服务端聚合，界面每 30 秒重读一次，几乎不打网络
- 点该标签或「刷新」按钮 = 立即同步；同步进行中显示「同步中…」
- 自动同步会主动让路：有签到/上传等任务在跑时不插队；未激活卡密时不去打供应商接口
- 反过来也一样：整轮签到、成长任务、代跑凭证保鲜现在会独占同一条串行通道，期间手动「刷新/同步」会直接提示已有任务在跑；定时窗口要是撞上同步，不算跑过，20 秒后的下一轮再试（窗口过了才由晚窗兜底）
- 激活卡密成功、或刚把开关打开，会立刻补一次同步，不用等满一个间隔
- 「刷新」「刷新积分」和自动同步走同一条串行通道：同一时刻只有一份在问供应商，撞上了会提示「已有任务在执行」而不是并发用同一个 token
- 积分**没变化就不写「积分记录」**，避免每 5 分钟一条把历史刷满；日志同理，只有出现变化或失败时才留一行
- 点「刷新」后账号列表、今日看板和积分记录是在同步结束时才更新（不是先画一遍旧数据）；界面每 30 秒的重读只在数据真的变了时才重建列表，滚动位置和选中项不会被打断
- 不想自动查积分：设置 → 本机选项 → 取消「自动同步状态与积分」（关掉后仍可手动点标签同步），间隔也在同一处填（1~240 分钟）

## 日志

- 「实时日志」每条都带本地时间，跨天的记录会显示成 `MM-DD HH:MM:SS`，不会再把昨天的 15:31 混进今天的 14:55 里
- 写日志走内存缓冲、每 2 秒落盘一次，退出程序时补写最后一次；因此强制结束进程最多丢最近 2 秒的日志
- 实时日志只有一个写入点（界面），旧版本会把调度日志重复存两行——历史上同秒重复的行是遗留数据，点「清理实时日志」即可

## 授权与传输安全

- 卡密激活后本机缓存 `ticket`，5 分钟由后台守卫在线校验一次；**只有服务端明确拒绝**（卡密到期/被吊销）才会踢回激活页并清掉票据。断网、加密通道建不起来只累计失败次数，不踢人。
- 被踢后重新输入有效卡密即可恢复（守卫会自动重启），无需重启程序。
- 与授权/代跑服务默认走加密信封（RSA-OAEP 包 AES-256-GCM）。两个开关在 `data\settings.json` 里（界面没有输入框，需退出程序后手动改）：
  - `allow_insecure_transport`：是否允许明文 HTTP。**当前授权服务器尚未配 TLS，默认开启**；服务端配好证书后建议关掉。
  - `allow_plain_fallback`：加密通道失败时是否允许退回明文请求。**默认关闭**——否则中间人只要干扰一次加密握手，就能把卡密和 ticket 降级成裸明文。仅在授权服务器证书异常且网络可信时临时打开。
- 界面上不展示 `ticket` 与卡密原文，日志与错误消息统一脱敏（`token=…`、JWT、长随机串会替换成 `***`）。

## 代挂额度与联系邮箱

- 「可挂载账号数」以服务端**代挂额度**为准（`/api/points-checkin/entitlement/info` 的 `quota`，管理端按卡密/卡种配置在 `checkin_entitlement`）。顶部额度标签显示的就是这个数；离线时暂时退回卡密缓存里的 `accountLimit`，注意它是**设备座位数**、不是账号额度，联网后会立刻校正回 `quota`。
- 换卡密（重新激活）后会马上重拉额度，不会继续按旧卡的额度判断。
- 额度只统计「启用中」的账号：停用不占额度，也不会在额度已满时拦住你入库。
- **服务器代跑（上传凭证）前必须先绑定并验证联系邮箱**：账号签到异常时服务端往这个邮箱发通知。未绑定时点「上传代跑 / 设为服务器代跑」会直接弹出绑定框（顶部额度标签也能点）；Tkinter 界面会弹输入框引导。
- 服务端不可达时不会因「查不到绑定状态」而拦截上传——绑定与额度最终由服务端裁决。

## 账号列表与代跑记录

- 列表是「本机账号 + 服务器代跑记录」的**合并视图**：同一个代挂账号只显示一行，以本机 id 为准，服务器那边只回填运行状态（启用/最近成功/最近错误）。这类记录不落盘，服务端删掉后本机不会再残留幽灵账号。
- 标了「仅服务器」的行是别的设备上传的代跑记录，本机没有它的凭证：不能改模式、不能查积分，只能删除（删除会真的删掉服务端记录）。
- **「删除」会连带删除服务器上的代跑记录**；而把模式改回「本机」并不会停止代跑——服务器记录还在，它会继续代跑，界面此时会明确提示而不是假装已切换。

## 存储与明文降级

账号、账密、票据都用 Windows DPAPI 按当前用户加密落盘。若 DPAPI 不可用（如组策略限制），程序会退回明文写入，同时：

- 在数据目录生成 `STORAGE_WARNING.txt`，记下每次降级的原因和时间；
- 启动时在日志里打印 `[警告]`。

看到该警告请尽快排查（换机器/换用户配置），期间导出的备份包也是明文，不要外发。

## 备份与恢复

「设置 → 备份数据」把账号、日志、积分记录、票据缓存和 `settings.json` 打成 `data\backup\checkintool_backup_*.zip`；「恢复数据」选回该 zip。

- 恢复只接受白名单内的文件，单文件超过 20MB 直接拒绝，避免被构造出的压缩包写越界。
- 备份里含 token 与（DPAPI 加密的）账密，请当作密码管理。
- 换机器恢复后设备指纹会变，卡密若绑了设备数需先在管理端清理旧设备。

## 重试与耗时

网络失败与 Trae 9074 会指数退避重试（单次等待有上限，并有总时长预算：Trae ≈3 分钟、WorkBuddy ≈1.5 分钟），超时即按失败记录，避免一个账号把后面排队的账号拖死。
